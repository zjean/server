## Goal

A non-admin user can upload a file (and eventually a folder) into `/v2/personal` without leaving v2. Progress is visible in the existing v2 transfers popover.

## Non-goals for 4.2

- **Uploads to Spaces** (different route base — needs service-shape work). Only `/v2/personal` in 4.2.
- **Overwrite UI polish.** Classic uses a ngx-bootstrap modal; v2 has no confirm-dialog primitive yet (lands in 4.6). v1 behavior: if the server rejects a duplicate, the failure shows in the transfers popover with the error — no interactive prompt.
- **Upload into a subfolder without navigating there.** You upload to the folder you're in.
- **Chunked / resumable uploads** for very large files.
- **Pause / cancel / retry.** Kick off, wait, see result.

## The classic service — how we reuse it

`frontend/src/app/applications/files/services/files-upload.service.ts` already does everything we need:

- `addFiles(files, overwrite)` — core entry point. Groups files by top-level key (file or folder), creates one `FileTask` per group, POSTs FormData to `${API_FILES_OPERATION_UPLOAD}/${filesService.currentRoute}/${key}`, pipes progress into the task.
- `onDropFiles(ev, exist)` — handles `DataTransfer` including `webkitGetAsEntry` recursion for folders.
- `supportUploadDirectory()` — feature-detects folder-upload support.

**The catch**: `addFiles` reads the destination from `FilesService.currentRoute` — a global set by the classic file browser. v2 has its own path state.

**The fix (MVP)**: before each call, set `filesService.currentRoute = <v2 path>`. Small, reversible; a tiny coupling leak into classic state. The "right" fix (add `addFilesTo(apiRoute, ...)` overload) is a mod of upstream and noisier to merge — defer unless MVP causes bugs.

## Architecture

**Consumer**: `personal.component.ts` only in 4.2. Spaces / subfolder flows come in later phases.

**New component**: `custom-v2/components/drop-zone.directive.ts` — thin attribute directive that wraps a host element, listens to `dragenter/over/leave/drop`, emits `(dropped)="onDrop($event)"` with the raw `DragEvent`, and toggles a `.drop-zone--active` class for hover styling. Keeps `personal.component.ts` focused on flow, not DOM events.

**New helper**: `personal.component.ts` grows an `uploadToCurrentFolder(files: FileList | File[], opts?: { folder?: boolean })` method that:
1. Builds the current-folder API route from `pathSegments()`.
2. Sets `filesService.currentRoute = <that route>`.
3. Calls `filesUploadService.addFiles([...files], /* overwrite */ false)` — tasks auto-populate the transfers popover.

**Toolbar**: the `Upload` button in `personal.component.html` is already present (disabled). Wire it to open a hidden `<input type="file" multiple>` via `.click()`, then feed the `change` event files into `uploadToCurrentFolder`.

**Folder upload**: a second hidden `<input type="file" multiple webkitdirectory>`. To avoid a second toolbar button, add an adjacent dropdown caret that flips between "file" and "folder" mode (or: keep it simple for 4.2 and just do files; spec folder upload in 4.3 with the "New" dropdown). **Recommendation**: files-only in 4.2, folder in 4.3. Smaller, safer.

**Drop zone**: apply the directive to the `.personal__body` element so the whole main area accepts drops (including the empty state). Visual feedback: overlay with a dashed outline + "Drop files to upload" text.

## Post-upload UX

After each `addFiles` call resolves, refresh the folder listing:

```ts
await filesUploadService.addFiles(Array.from(files), false)
this.refresh()  // re-hits the same /spaces/browse endpoint the component already uses
```

Errors surface in the transfers popover automatically (classic code already sets `task.status = ERROR` and `task.result`).

## Scope trimming decisions

- **Drop zone is the body, not the window.** Less surprising; lower chance of hijacking the user's drag-select of text elsewhere in the UI.
- **No concurrency cap.** Classic has none either; browser handles it.
- **No progress in the toolbar button itself.** Transfers popover is the source of truth — don't duplicate state.
- **No optimistic local list update.** Wait for success, then `refresh()`. Simpler reasoning, prevents ghost rows on failure.

## Manual testing checklist

1. **Toolbar `Upload`** → OS file picker opens; pick 1 or 2 files → transfers popover shows progress, files appear after.
2. **Drag 3 files from Finder onto the body** → body shows drop overlay while dragging; on drop, overlay disappears and upload starts; after it ends, files are listed.
3. **Drag a file into a subfolder then release over parent** — uploads to the parent (current folder), not the subfolder row. (I.e. drop target granularity is the whole body, not per-row.)
4. **Upload a file with the same name as an existing one** → server responds with error; transfers popover shows the error row; file list unchanged.
5. **Upload a large file** → progress bar moves smoothly, completes, file appears.
6. **Navigate to a subfolder, upload** → uploads land in the subfolder, not at the root.
7. **Dutch locale** → "Uploaden" / drop-overlay string translates.
8. **Drag something that isn't a file** (e.g. selected text) over the drop zone → drop-zone overlay either doesn't appear or clears cleanly after release; no errors.

## Open questions before execution

1. **Folder upload in 4.2, or defer to 4.3?** Plan recommends defer — but if you'd rather have it, add a hidden `<input webkitdirectory>` alongside the files input and a two-option popover on the Upload button. ~+80 LOC.
2. **Drop zone visual** — dashed outline inside the body (current proposal), or a fullscreen overlay while dragging? Current proposal is safer (no interaction with the app rail / nav), but fullscreen feels more modern. Easy to change.
3. **Refresh-after-upload timing** — refresh once after *all* uploads resolve, or after each? Plan proposes once-at-end for simpler reasoning; if the user uploads 10 files and watches the list, they won't see anything until they're all done. Per-file refresh is chattier but more responsive. **Lean toward per-file if the folder listing endpoint is cheap** (it is — simple directory read).
